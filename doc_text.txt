StudyFlow — Phase 2 Backend Integration README

Next.js Web Application • Supabase Backend • UI-to-Data Integration

1. Objective

Turn the completed Phase 1 UI into a real data-driven web application using Supabase. Do not redesign the UI; connect the existing screens to persistent data. AI APIs are reserved for Phase 3.

2. Phase 2 Scope

Implement: Supabase project, PostgreSQL, Next.js Supabase client, schema, relationships, indexes, CRUD, development seed data, roadmaps, topics, progress, checklists, chat/conversation persistence, notes, document metadata/storage, quizzes, quiz attempts, coding problems, coding attempts, tasks, realtime, loading/error/empty states, and testing.

Do not implement: AI APIs, AI generation, RAG embeddings/vector search, AI memory, Flutter, Android synchronization, or production authentication.

Authentication is postponed, but keep user_id in the schema from day one.

3. Stack

Frontend: Next.js, TypeScript, Tailwind CSS, shadcn/ui, Framer Motion, Lucide React, Recharts, Monaco Editor, Zustand.

Backend: Supabase PostgreSQL, Supabase Storage, Supabase Realtime, and Edge Functions only when needed later.

Do not add Express, MongoDB, Redis, Firebase, Kubernetes, or a separate vector database unless a future requirement genuinely needs them.

4. Architecture

Next.js UI

  -> Hooks

  -> Service layer

  -> Supabase

  -> PostgreSQL / Storage / Realtime

Future:

Next.js Web <-> Supabase <-> Flutter Android

AI is not part of Phase 2.

16. Development User

Authentication is postponed.

Use a temporary development identifier such as DEV_USER_ID.

Every user-owned table still includes user_id.

Later:

DEV_USER_ID -> Supabase authenticated user.id

This prevents a future database redesign.

17. Realtime

Implement after CRUD is stable.

Example:

Browser Tab 1 -> Supabase update -> Realtime event -> Browser Tab 2 -> UI update

This prepares the same data layer for future Flutter synchronization.

Do not build Flutter in Phase 2.

19. Testing Checklist

Roadmap: create -> add topics -> nest -> reorder -> save -> reload.

Topic: open -> edit -> progress -> reload.

Checklist: add -> complete -> reload.

Chat: create -> add mock messages -> rename -> delete -> reload.

Notes: create -> edit -> save -> reload -> delete.

Knowledge: upload -> metadata -> display -> delete.

Quiz: create -> questions -> play -> attempt -> result.

Coding: create -> open -> mock submit -> save result.

Tasks: create -> complete -> edit -> delete.

Realtime: open two browser tabs, change data in one, verify the other updates.
